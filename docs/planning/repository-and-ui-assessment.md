## Verified provider semantics and engineering implications

The following are documentation findings, not claims about the currently running deployment. Pin and retest actual versions during implementation.

- VROOM v1.15 job priority influences which jobs are selected when some cannot be served; it does not enforce urgent-first visit order. Its usual optimization response can leave work unassigned, and an empty violations list is insufficient acceptance evidence. All times in one problem use a common origin. These require an application urgency strategy, complete requested-ID reconciliation and explicit time conversion. [VROOM v1.15 API](https://raw.githubusercontent.com/VROOM-Project/vroom/v1.15.0/docs/API.md)
- OSRM route/table requests use longitude before latitude; travel profiles depend on preprocessing. Application vehicle labels must map to the correct service/dataset. Route geometry and a basemap are separate products. [OSRM API](https://project-osrm.org/docs/v5.24.0/api/)
- Nominatim searches return geographic candidates; application confirmation and provenance remain necessary. A returned importance/rank is not a calibrated address-match percentage. [Nominatim Search API](https://nominatim.org/release-docs/latest/api/Search/)
- PMTiles offers read-only tiled archives accessed through HTTP range requests. MapLibre integration also requires a compatible style plus font/sprite assets. A self-hosted regional archive can avoid a separate dynamic tile database, but coverage, attribution, range serving and Arabic labels must be verified. [PMTiles](https://docs.protomaps.com/pmtiles/), [Protomaps with MapLibre](https://docs.protomaps.com/basemaps/maplibre)
- OpenID Connect supports separate application sessions through authorization-code flows. Keycloak's documentation rejects using the resource-owner-password flow for new integration. The proposed ERP/Tawsel shared identity authority should use a themed issuer login and code flow instead of copying ERP hashes or forwarding passwords on every action. [Keycloak OIDC](https://www.keycloak.org/securing-apps/oidc-layers)
- Fastify provides schema-based validation/serialization, but its default schema dialect must not be confused with OpenAPI 3.1's JSON Schema dialect. Configure and verify the chosen validator/compiler; keep schemas trusted and versioned. [Fastify validation](https://fastify.dev/docs/latest/Reference/Validation-and-Serialization/)
- PostgreSQL row locks can protect business transitions; `SKIP LOCKED` can support competing queue workers. Its skipped-row view is not suitable as a coherent monitoring snapshot. [PostgreSQL SELECT](https://www.postgresql.org/docs/current/sql-select.html)
- IndexedDB transactions through Dexie support atomic local action/projection writes and database upgrades. Network calls should remain outside those local transactions. [Dexie design](https://dexie.org/docs/Tutorial/Design)
- Browser quota and eviction mean a PWA cannot promise permanent unsent-data retention against storage clearing or device loss. Request persistence, detect write failure and verify target devices. [Browser storage limits](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)
- Workbox background sync has a fallback and retention behavior; it is not a universal guaranteed background transport. Use a domain action queue with explicit durable state rather than an expiring raw-request queue as the only business record. [Workbox background sync](https://developer.chrome.com/docs/workbox/modules/workbox-background-sync)
- Vite is suitable for the proposed separately deployed frontend build; Dokploy supports Compose deployment. Neither choice proves this combined stack fits the user's server. [Vite guide](https://vite.dev/guide/), [Dokploy Compose](https://docs.dokploy.com/docs/core/docker-compose)
